# UI 设计与演示模块

更新日期：2026-11-03。首版目标：从已有材料制作设计一致、可操作、可重复展示的独立演示，并支持后续修改与恢复。

## 从哪里开始

唯一角色入口是 [ui-design.md](ui-design.md)。例如可以显式要求：“读取 UI 角色主文档，依据指定材料讨论这套演示。”角色按需读取上游方法和本地模板，不要求用户逐项提供内部路径。

讨论模块建设、核对授权与进度时读取[建设方案](ui-module-construction-plan.md)；日常 UI 工作不必加载全部建设历史。操作文件前读取[文件操作约定](agent-file-workflow.md)。

开发步骤 5 时读取[最小工具链逐步开发方案](ui-step5-development-plan.md)，从 S5-00 按依赖推进 5A／5B／5C；它组织开发次序，准确接口仍以工具实施说明为准。

测试开发结果时读取[步骤 5 验收执行文档](ui-step5-acceptance-test.md)：先检查是否具备实现，再在临时副本执行主线与保护验证，按实际证据报告，不修改正式实现或测试标准。

## 来源和模板怎样使用

methods/develop-helper 直接指向工作区原始 Develop_Helper，保留相邻文件关系。只显式读取适用文件，不加载上游 Router 或全流程；软链不提供技术只读保护。

本地模板由上游 ui-style-template.md 复制适配，保留全局视觉、组件、逐页设计与验收骨架，增加 PRD／场景双来源、模拟范围、刷新与重置、打开说明、输入版本与反馈边界。上游原文不改；具体差异记录在 SOURCES.json。

业务成果归明确的业务项目或授权试验目录，不写入本模块、方法原件或模板。步骤 4 默认采用 docs/prototypes/demo/ 页面、docs/ui-style.md 设计与 ui/artifact-manifest.json 清单，合法已有布局可沿用；外部试做源保持只读。准确限制及导入映射见实施说明，不代表当前存在可写接口或自动登记。

没有完整 PRD 的独立演示可使用足够的页面／场景说明；不伪造 REQ／AC。工程开发再核对相关需求、技术契约与正式用途确认，不自动把演示认可当工程放行。

## 运行依赖与独立边界

设计方法依赖 Develop_Helper 原文可读。UI 文件工具显式复用 requirements 本地共享基础的十文件闭包；受控加载器、运行基线和写保护链已在步骤 5 接通，并通过临时环境自验与门 2 独立验收。

显式目录模式下，六个工具每次以完整 `project_path` 绑定项目，候选、检查、接受、历史与恢复沿用同一持久身份；缺省及 `legacy_rooted` 保留旧根直接子目录规则。外部导入仍只来自启动时 `--import-root` 授权的独立位置，持久候选中的 `root` 不会自行恢复授权。

不要求需求 Agent／需求 MCP／方案服务在线，不使用旧 buzz-develop-helper 运行代码；仍不能只复制本目录就声称方法、共享代码、配置与客户端已具备。跨机器需要按来源与版本恢复映射。

来源或软链变化先核对影响，不静默刷新 SOURCES 或上游锁。`runtime_sources` 摘要漂移会阻断调用，其他文档记录仍需人工维护。静态文件入口不保证客户端自动读规则；真实读取与调用证据在步骤 9 单独验证。
