## 3. 已核对的依赖闭包

所有文件来自 `fusion-runtime/workflows/requirements/file_tools/`，实际摘要见机器证据的 source_index。它们依赖 Python 标准库；涉及项目仓库边界时额外调用本机 Git。

| 文件 | 拟复用能力 | 本轮实际覆盖 |
| --- | --- | --- |
| `__init__.py` | 显式包入口 | 无写入导入、临时别名包加载 |
| `check_foundation.py` | 配置、路径、方法链接、上游内容基线 | 实际基础只读检查；临时副本正向及缺配置、目录重叠、断入口、来源漂移拒绝 |
| `project_state.py` | 共享锁、单文件原子替换 | 临时项目锁冲突／释放、替换后复读；没有声称验证多文件事务 |
| `project_init.py` | 项目定位、ID／目录、初始化与读取 | 中文目录、身份绑定、错误绑定拒绝、临时基础文件初始化及 Git 只读边界检查 |
| `requirements.py` | 读取正文、缺失文件、摘要与路径保护 | 四文件 context、正文／缺失状态、路径越界拒绝；没有调用需求或 PRD 保存器 |
| `artifact_records.py` | UI 文件集合与登记只读核验 | 文本及二进制成员、跨目录清单、入口、摘要不符与软链拒绝、无登记状态 |
| `confirmation_records.py` | 正式确认及快照只读核验 | 成功导入，缺少 decisions 的只读读取；未构造有效正式确认或测试完整快照正向链 |
| `project_info.py` | 项目选项、规范解析 | 初始化选项、读取记录、null 不回退 default、default 规范目录定位 |
| `recovery.py` | 已有需求／方案恢复及确认核验组织 | 临时无 PRD／确认场景的只读恢复及本地校验器加载；不是 UI 恢复工具 |

其中 `project_info` 既有懒加载初始化用途，也供项目选项读取使用；`confirmation_records` 与 `recovery` 属于只读恢复扩展。当前验证采用包含这些能力的 9 文件集合，不意味着未来每个 UI 操作都需要加载全部文件。

静态遍历包括函数内部的懒导入和包外兼容导入分支。全部导入要么属于这组本地模块，要么属于标准库；没有第三方 Python 包、旧 scripts、方案服务或实验运行时依赖。

实际运行仍使用包方式。旧模块中保留的裸导入兼容分支不作为 UI 新入口；后续加载器应固定来源、采用版本和公开符号，不把目录直接塞入任意全局搜索路径。

## 4. 隔离方法

1. 创建系统临时目录，复制上述 9 文件、现有锁记录与上游内容；不复制 `buzz-develop-helper`、`fusion-runtime-lab` 或 Solution Designer 运行代码。
2. 上游副本按现有 snapshot 排除规则复制，复制后重新核对 250 项内容指纹与真实锁一致。
3. 只在临时目录生成测试配置、业务项目、模拟 UI 文件集合及两个方法链接。临时 UI 方法链接只是验证夹具，不是实际 UI 模块入口已经建立。
4. 启动新进程，使用 `-I -S -B`，清除继承的 Python 路径／启动设置及相关 Git 环境变量；禁用用户 site、site-packages 和字节码缓存。
5. 模块以专用别名从临时 foundation 显式加载，检查每个模块来源。Python 审计钩子拒绝子进程打开原工作区；任何源码回读都会令检查失败。
6. 子进程中仅允许 Git `rev-parse` 这类当前探针需要的只读调用，不运行初始化 Git、提交、网络或其他外部命令。
7. 缺模块场景另启全新进程，移走临时副本中的 artifact_records.py，验证缺失直接报错、不从旧目录或模块缓存回退。
8. 比较导入前后临时树、只读恢复前后业务树，以及运行前后真实共享文件、锁、配置和方法链接；实际来源未变化。

临时目录在检查后清理。机器证据中的临时路径是当次运行记录，不是可继续访问的成果位置。

这属于有明确检查边界的进程与文件验证；不将 Python 审计钩子宣称为通用安全沙箱或生产加载器的实现。
