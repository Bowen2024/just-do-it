## 2. 实际设计产出

候选仅在本轮工具参数中使用，没有写入业务目录，也没有生成自称已保存的受管头。下面记录设计要点与评审依据，不替代完整业务工程交付。

### 2.1 完整处理链

用户粘贴纪要 → 本进程保留原文和版本 → 模型完整抽取 → 本地结构与原文证据校验 → 两个分区完整显示。

失败时不显示半份清单、空清单或旧清单作为本次结果；保留原文，用户可重试、重新输入完整修订稿或退出。只有两个分区都为空才进入“检查输入”。

### 2.2 真实模块边界

| 设计编号 | 职责 | 输出与关键边界 |
| --- | --- | --- |
| DES-001 | 多行输入与用户事件 | 原文、revision；空白输入本地拒绝 |
| DES-002 | 模型适配器 | 完整响应或类型化失败；不虚构供应商 API |
| DES-003 | 校验及归一化 | 两个完整分区或整批失败；不悄悄删掉不合格条目 |
| DES-004 | 终端呈现 | 全部人员；缺失字段占位；原话日期；控制字符转义 |
| DES-005 | 会话控制 | 单请求、人工重试、修订后重算、退出释放应用引用 |

没有新增 HTTP 服务、数据库、队列、登录或模型工具执行。目录和 Python 实现为候选建议；业务程序尚未编写。

### 2.3 数据与模型分工

两类待办共用 task、evidence_text、owner_text、owner_evidence、deadline_text 字段。未知负责人和日期使用 null，由渲染器显示“待分配”“未写明”。

本地校验检查字段、类型、完整响应和原文证据关系：证据必须来自同版原文，人名及时间必须位于该事项证据中。校验失败整批拒绝。模型承担行动识别、明确／可能分类和负责关系判断。

核心限制：原文出现人名不能证明这个人被指派负责；合法 JSON 不能证明无漏项。提示词和原文包含校验都不能替代模型质量评估。

### 2.4 状态、异常与生命周期

状态为 INPUT → RUNNING → RESULT / EMPTY / FAILED，等待状态可退出。重试沿用同一 revision 原文、创建新 attempt；重新输入增加 revision，清空旧结果并完整重新请求和校验。

已分析：空输入、缺配置、网络失败、限流、超时、拒绝、响应截断、坏 JSON、证据不符、仅可能待办、重试再次失败、显示失败、退出和远端迟到结果。

不写本地纪要和识别结果，不承诺跨进程恢复；退出释放应用引用，不承诺操作系统安全擦除或供应商删除。手动重试可能再次计费；供应商端是否停止及内部自动重试需选型后核对。

终端风险：若用 Ctrl-D 结束多行输入，不能默认继续从同一个已 EOF 的 stdin 读取菜单。候选提出控制终端 /dev/tty 与输入重开方式，需要真实 macOS 终端最小验证；尚未执行，不能写成已解决。

### 2.5 技术时序与交付深度

候选含用户、CLI／会话、适配器、模型、校验器、渲染器参与者的时序，覆盖正常、服务失败、校验失败、空结果、再次失败和修订重算。仅核对 Mermaid 源文本，未渲染。

确定性模块已有输入、处理步骤、状态、输出、失败和验证位置。模型适配器尚缺服务商、准确版本、协议、限额、响应完成标志、留存政策和调用预算；这些需后续定向核实，不能用“调用模型”四个字视为工程设计完成。
